# mc-16: AiPipe Metering Middleware

## Objective
Read AiPipe response headers after every proxied request and record to usage ledger. MC is a CONSUMER — AiPipe is the source of truth for costs and tokens.

## Requirements
1. `src/lib/usage/meter.ts`:
   - `recordUsage(tenantId: number, aipipeHeaders: Headers): Promise<void>`
   - Reads from AiPipe response headers:
     - `X-AiPipe-Model` → model
     - `X-AiPipe-Provider` → provider
     - `X-AiPipe-Tokens-In` → tokensIn
     - `X-AiPipe-Tokens-Out` → tokensOut
     - `X-AiPipe-Cost-USD` → costUsd
     - `X-AiPipe-Hypothetical-Cost-USD` → hypotheticalCostUsd
     - `X-AiPipe-Saved-USD` → savedUsd
     - `X-AiPipe-Cache` → cacheHit (true if "hit")
     - `X-AiPipe-Request-Id` → requestId
   - Inserts row into `usage_ledger`
   - Upserts daily + monthly `usage_summary` (increment counters)
2. Wire into AiPipe proxy routes:
   - `src/app/api/aipipe/proxy/chat/route.ts` — after upstream response
   - `src/app/api/aipipe/proxy/messages/route.ts` — after upstream response
3. Fire-and-forget: metering MUST NOT slow down the response. Use `Promise` without await (or `waitUntil` if available).
4. Graceful fallback: if any header is missing, log warning but don't fail the request.
5. Tests: mock headers → verify ledger insert, verify summary upsert, missing headers don't throw

## NOT building
- Cost calculation (AiPipe does that)
- Token counting (AiPipe does that)
- Budget checks (mc-17)

## Dependencies
- mc-15 (usage ledger schema)
